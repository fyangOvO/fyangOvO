## 并发锁存档事故（godot-engineer 发现，结论成立）

**两 Godot 进程共享 `%APPDATA%\Godot\app_userdata\七傳說\saves` ⇒ Windows 文件锁 ⇒ `rename` 失败**
⇒ 回归被刷成**假红**（`verify_save` 挂死 180s，exit=124）。**对照实验干净**：同代码同进程数，
只把 `APPDATA` 指向独立目录 → **39/39 全绿 exit 0**。
**⚠️ 这条对主理人自己的 `--verify` 同样成立。**

## 系统性缺陷：42 个 verify 脚本把「失败」伪装成「挂死」

`game/tools/` 下 **42 个** `verify_*.gd` **全部**把 `get_tree().quit(0 if _fail == 0 else 1)`
放在 `_ready()` **最后一行** ⇒ 中途任何运行时错误都让 `_ready()` 中断 ⇒ **quit 永不执行
⇒ 进程永久挂起**，CI 上表现为「卡满超时」且**退出码是 124 不是 1（失败信号丢失）**。
**已派单**：① 全部加 60s 失败兜底看门狗（含**证伪实验**：故意插崩 → 实测 60s 内 exit 1）；

### 环境坑（本轮新踩）
MSYS bash 偶发 `dofork: child died waiting for dll loading, errno 11` ⇒ **整条命令输出为空**。

⚠️ 另一个坑：**后台运行（`run_in_background`）时 `timeout "$GODOT"` 会报路径不存在**（`No such file or directory`）
