### 1.3 五個關鍵工程發現（**後續批次必讀**）

1. **新建 `class_name` 後 headless 報「Could not find type」** —— 全局類快取
   （`.godot/global_script_class_cache.cfg`）未更新。修法：跑一次
   `godot --headless --editor --quit --path .` 重建快取。**（本輪新踩坑，已寫入 IRON-RULES）**
2. **`HitQuery.circle` 排除與圓心距離 ≈ 0 的節點**（防自傷）⇒ 以**目標為圓心**的範圍傷害
   （燼誓引爆）會漏掉目標本身。修法：area 結算時**顯式帶上 `ctx.target`** 再併入 circle 結果。
3. **`EventBus.damage_taken` 只有近戰會發**（`enemy_base._attack_player`）；遠程
   （`enemy_projectile.gd`）與拋擲（`_lob_impact`）**漏發**。故 `on_damage_taken`/`reflect` 改用
   `HealthComponent.damaged_hook` 承載（覆蓋全部傷害來源，且不動 `juice_fx` 監聽的公開信號）。
4. **`on_pickup_gold` 的真源是 `loot_picked_up`（`type=="gold"`），不是 `gold_changed`** ——
   `gold_changed` 全庫只有 `run_shop.gd` 一處在用，**且簽名不符**（信號 2 參數 / emit 1 參數）。
5. **`LegendaryEffectSystem` 的 `stack` 中間態結果無 `type` 鍵**（只有 `{stacks, stacks_until}`）
   ⇒ 執行器必須**按 `phase` 過濾**（`phase=="stack"` 直接跳過），否則每次疊層都刷「未實現執行器」日誌。

### 2.3 三个关键工程发现（**后续批次必读**）

1. **`add_child()` 同步触发 `_ready()`，早于 `global_position` 赋值** ⇒ 落点相关结算
   （`meteor` 的落地爆发）会打在**原点**。修法：两段式 `begin()`。（本批自查发现，已写 `IRON-RULES` ⑨）
2. **`CombatMetrics` 的「同步窗口」框不住延迟命中**：B0 时投射物/地面是同步结算 ⇒ 命中恰好
   在 `begin_cast`/`end_cast` 之间；换成真实实体后命中落在窗口外 ⇒ `note_skill_hit()` 静默 return
   ⇒ `hits=0` + `whiffs=1`（打中了却算放空）。**这是本批引入的埋点回归**，已修。
3. **多发射射物的伤害被 B0 低估**：B0 的 `_execute_projectile` 注释写「伤害 = multiplier ×
   projectile_count」，但代码只 `_hit(targets[0])` **一发**。本批改为 N 发独立结算 ⇒
   `multishot` 全中回到设计值 **300%**（§5.1「全中」口径）。
